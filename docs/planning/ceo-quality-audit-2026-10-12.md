## 2. How the system is built (so the gaps are read against the design, not against a generic chatbot)
The CEO is a **closed-catalog orchestrator by decision**, not a free planner: `CLAUDE.md` forbids LangGraph/LangChain orchestration and any LLM-chosen code path ("an LLM must never silently decide what code runs or touch a number"). A turn is: admission, one classification (a rules router runs first, then the model, schema-constrained), deterministic plan validation against a closed catalog, per-leg permission/attachment/entitlement checks, parallel legs through one choke point, an evidence table resolved through provenance refs, one composition, a numeral/provenance gate with a fixed template fallback, persisted messages, findings and timings. Five playbooks exist (`PROFIT_DIAGNOSIS`, `CASH_AND_LEAK_CHECK`, `COMPETITOR_PRICE_IMPACT`, `NEW_PRODUCT_DECISION`, `BUSINESS_BRIEFING`). Conflicts between stored results are detected by code and shown as a conflict block, never averaged (record, spec 6.32). The master task's "adaptive orchestration" and "multi-agent investigation planning" therefore have to be delivered **as additional closed playbooks and routing rules**, not as a model that plans freely.
